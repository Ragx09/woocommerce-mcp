# API Contracts

> Status: **draft**. Base path `https://app.<domain>`. JSON everywhere. Errors use `{ "error": "<code>", "message": "<human text>" }`. The session cookie is `sid` (httpOnly, SameSite=Strict). Mutating `/api` requests (POST/PUT/PATCH/DELETE) from a browser must carry `Origin` equal to the public origin (or `Sec-Fetch-Site: same-origin`), otherwise 403 `forbidden` "cross-origin request refused" (AUTH-03). Every response carries `X-Request-Id` (a server-generated UUID; a client-sent one is ignored), which appears on every gateway log line of that request — quote it when reporting a problem.

Security headers on every gateway answer, `/mcp` included (SEC-07, F-WEB-9): `X-Content-Type-Options: nosniff`, `X-Frame-Options: DENY`, `Content-Security-Policy: default-src 'none'; frame-ancestors 'none'`, `Referrer-Policy: no-referrer`, `Cache-Control: no-store`; `Strict-Transport-Security: max-age=31536000` when the request came in over TLS through the trusted proxy.

Every `/api` route declares its access (`public`, `session`, `admin`) in code; the guard runs before the body is parsed, so an anonymous request gets 401 and a member on an admin route 403 regardless of the body (AUTH-10).

## Internal routes (provisioner → gateway)
Not in the Ingress; the NetworkPolicy admits only the provisioner pod; every request carries `x-platform-signature: t=<unix s>,v1=<HMAC-SHA256 over time, method, path and body hash>` (60 s window, constant-time compare); every handler is idempotent.
| Path | Body | Effect |
|---|---|---|
| `POST /internal/stores/:id/ready` | `{wooMcpUrl, wooMcpToken, adminUser, adminPassword}` | registers upstream `woo-<slug>` (URL must be this store's own woo-mcp Service), stores the wp-admin password encrypted, status `ready` |
| `POST /internal/stores/:id/failed` | `{reason}` | status `failed` (only from `provisioning`) |
| `POST /internal/stores/:id/deleted` | `{}` | removes leftovers, status `deleted` |
| `POST /internal/stores/:id/runtime` | `{pods:{ready,total}, quota?}` | numbers only, validated; shown to admins |
| `POST /internal/stores/:id/missing` | `{}` | a ready store's namespace is gone (3 consecutive 404s): status `failed` with that reason, server unregistered |
| `POST /internal/stores/:id/password-reset` | `{ok, reason?}` | success moves the sealed new password to the viewable-once slot; failure keeps the reason |
| `POST /internal/hosted/:id/ready` | `{url}` | registers the hosted server (own Service URL only, no credential, members none) |
| `POST /internal/hosted/:id/failed`, `/deleted`, `/runtime`, `/missing` | as for stores | same semantics |

## Error codes
`unauthenticated` (401), `invalid_credentials` (401, login), `forbidden` (403), `not_found` (404), `validation_failed` (400, with `issues`), `conflict` (409, e.g. duplicate slug), `ssrf_blocked` (400), `invite_used` / `invite_expired` (410), `rate_limited` (429), `internal` (500). Chat: `chat_disabled` (503), `chat_busy` (429), `llm_rate_limited` (429), `llm_timeout` (504), `llm_unavailable` / `llm_error` / `chat_failed` (502).

`/mcp` (JSON-RPC, GW-08): `tools/call` with an unknown or malformed name → error `-32602` with `data.code = "unknown_tool"`; disabled upstream → `-32602`, `data.code = "upstream_disabled"`; a tool the caller's role may not use → `-32602`, `data.code = "tool_forbidden"` (BON-01); registry (DB) failure → `-32603 "upstream registry unavailable"`. Upstream problems are returned as a tool result with `isError: true` and text `upstream_unreachable: …` / `upstream_timeout: …` / `upstream_error: …`; an upstream's own `isError` result is passed through unchanged.
